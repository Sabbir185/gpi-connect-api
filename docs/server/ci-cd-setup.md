# Server Deployment & CI/CD Setup Guide

This guide explains how the GitHub Actions CI/CD pipeline (`.github/workflows/ci-cd.yml`) deploys the `gpi-connect-api` backend to your remote production server, and how to configure all required GitHub Secrets, Variables, and server prerequisites.

---

## 1. Required GitHub Secrets & Variables

Go to your repository on GitHub:
**Settings** ➔ **Secrets and variables** ➔ **Actions**

> [!NOTE]
> The workflow uses `environment: production`. You can configure these secrets/variables under **Environments** (`production`) or globally under **Repository secrets / variables**.

### A. Secrets (`Repository secrets` or `Environment secrets`)

| Secret Name | Description | Example / Format |
| :--- | :--- | :--- |
| **`DEPLOY_USER`** | SSH username on your remote server | `ubuntu` or `root` |
| **`DEPLOY_HOST`** | Public IP address or domain of the remote server | `159.65.xx.xx` or `api.gpiconnect.com` |
| **`DEPLOY_SSH_KEY`** | Private SSH Key (ed25519) for passwordless login | Full content of private key file (`~/.ssh/github_deploy`) |
| **`DEPLOY_KNOWN_HOSTS`** | Host key fingerprint generated by `ssh-keyscan` | Output of `ssh-keyscan -H <DEPLOY_HOST>` |

> **`GITHUB_TOKEN`**: Automatically provided by GitHub Actions runner with `packages: write` permissions. You do **not** need to create this manually.

### B. Variables (`Repository variables` or `Environment variables`)

| Variable Name | Description | Example |
| :--- | :--- | :--- |
| **`DEPLOY_PATH`** | Target directory path on your server where `compose.yaml` and `.env` live | `/home/ubuntu/gpi-connect-api` |

## 2. Generating SSH Keys & Known Hosts

Run these commands on your local machine or server to create a dedicated deploy key:

### Step 1: Generate a dedicated SSH key pair
```bash
ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/github_deploy
```
This generates two files:
- `~/.ssh/github_deploy` (Private Key — keep secure!)
- `~/.ssh/github_deploy.pub` (Public Key)

### Step 2: Add Public Key to the Remote Server
Add the public key to the remote user's `~/.ssh/authorized_keys` file:
```bash
ssh-copy-id -i ~/.ssh/github_deploy.pub <DEPLOY_USER>@<DEPLOY_HOST>
```
*Or manually copy the single-line text from `~/.ssh/github_deploy.pub` and append it into `~/.ssh/authorized_keys` on your server.*

Test your connection:
```bash
ssh -i ~/.ssh/github_deploy <DEPLOY_USER>@<DEPLOY_HOST>
```

### Step 3: Add `DEPLOY_SSH_KEY` to GitHub Secrets
Display the full content of your private key:
```bash
cat ~/.ssh/github_deploy
```
Copy everything from `-----BEGIN OPENSSH PRIVATE KEY-----` to `-----END OPENSSH PRIVATE KEY-----` and paste it as the value for **`DEPLOY_SSH_KEY`**.

### Step 4: Add `DEPLOY_KNOWN_HOSTS` to GitHub Secrets
Run `ssh-keyscan` with your server's IP address:
```bash
ssh-keyscan -H <DEPLOY_HOST>
```
Copy the full terminal output and paste it as the value for **`DEPLOY_KNOWN_HOSTS`**. This allows GitHub Actions to securely verify your server's identity without interactive confirmation prompts.

## 3. Remote Server Setup & Prerequisites

Before the first deployment runs, ensure the following steps are completed on your remote server:

### 1. Install Docker & Docker Compose
```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
```

Ensure your deploy user can run Docker commands without `sudo`:
```bash
sudo usermod -aG docker $USER
```
*(If already logged in, log out and log back in for group changes to take effect, then test with `docker ps`).*

### 2. Create Application Directory
Create the folder specified in `DEPLOY_PATH`:
```bash
mkdir -p /home/ubuntu/gpi-connect-api
cd /home/ubuntu/gpi-connect-api
```

### 3. Create `.env` on the Server
The CI/CD pipeline automatically copies `compose.yaml` on every deployment, but sensitive runtime credentials must live in `/home/ubuntu/gpi-connect-api/.env` on the server.

Create `/home/ubuntu/gpi-connect-api/.env`:
```env
PORT=8080
DATABASE_URL=postgres://user:password@host:5432/dbname?sslmode=disable
REDIS_URL=redis://default:password@host:6379
JWT_SECRET=your-production-jwt-secret
# Add any third-party credentials (SMS, Firebase, Storage, etc.)
```

## 4. How the Deployment Pipeline Works

Every push to `main` triggers `.github/workflows/ci-cd.yml`:
1. **`check` job**:
   - Verifies formatting (`gofmt -l .`).
   - Runs static analysis (`go vet ./...`).
   - Executes unit tests (`go test ./...`).
2. **`deploy` job** (runs automatically after `check` succeeds):
   - Sets up Docker Buildx with GitHub Actions layer caching.
   - Builds container image and pushes `ghcr.io/sabbir185/gpi-connect-api:<sha>` and `:latest`.
   - Connects to remote server over SSH.
   - Synchronizes `compose.yaml` to `$APP_DIR`.
   - Authenticates Docker on the server with GitHub Container Registry.
   - Pulls the latest image and performs zero-downtime rolling restart (`docker compose up -d --wait --remove-orphans`).
   - Prunes old unused container images (`docker image prune -f`).
   - Logs out of the registry.

## 5. Troubleshooting

- **Host key verification failed**:
  - Run `ssh-keyscan -H <DEPLOY_HOST>` again and update the `DEPLOY_KNOWN_HOSTS` secret.
- **Permission denied (publickey)**:
  - Verify that `~/.ssh/authorized_keys` permissions on the server are correct:
    ```bash
    chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
    ```
- **Docker permission denied**:
  - Ensure the user is added to the docker group: `sudo usermod -aG docker <DEPLOY_USER>`.
- **View Live Server Logs**:
  ```bash
  cd /home/ubuntu/gpi-connect-api
  docker compose logs -f --tail=100
  ```
